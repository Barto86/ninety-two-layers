Why I made this

Much of my career has been spent making invisible processes visible. In visual effects, a fluid simulation is a set of equations until someone decides how it should look. In animation, a character’s weight and intention exist only once they have been drawn into motion. This piece applies the same habit of mind to a large language model.

I made it in response to a phrase I hear often, in studios and in lecture theatres: that AI is just a tool. I understand why the phrase is reassuring, because it leaves authorship firmly with the person using the system. I do not think it is accurate. A tool does what its maker specified, and nobody specified, line by line, what this system does. What happens inside it between a prompt and a reply is a process we are still learning to describe.

The visualisation is an interpretation. It is built to the published architecture of a single model, and it is clear about where it simulates activity. The piece starts from a simple question, and it is the kind of question practitioners ask of any process they work with: if we could watch it unfold, what would we recognise in it?

Reading the specimen

The first view draws the model as a histologist might draw a section of cortex. Input enters at the base, and the signal rises through the layers. Each point is an expert sub-network, 512 in each of the 92 layers and 47,104 in all. At this density each point stands in for roughly 4.7 billion weights, so the image is a compression, in the same way that any drawing of a brain is.

Resting expertAn expert this token did not call on. Most of the tissue is quiet most of the time, which is true of the cortex as well.
Firing expertOne of the 10 experts the router selected for this token in this layer. The arc that reaches it plays the part of a dendrite, carrying the signal in.
Shared expertThe node at the centre of each layer. Every token passes through it.
Residual streamThe vertical threads, one for each token. Each layer reads from its thread and writes back to it, much as an axon carries a signal forward.
Attention arcDrawn in every fourth layer, where full attention allows a token to draw on earlier tokens. The rings in the remaining layers mark the linear-attention memory being updated.
AscentThe full climb through 92 layers happens once for every token the model writes. A single word of reply costs one complete pass.

Reading the exposure sheet

The second view borrows the animator’s exposure sheet, the document that tells a camera operator what to shoot, frame by frame. Here each row is a frame and each frame is a token. The columns are the levels of a cel stack, except that they are the 92 layers, composited from left to right to resolve each token. Every eighth row is ruled more heavily, and every sixteenth carries a footage mark, as it would on a sheet for 35mm film.

I found the comparison closer than I expected. A language model works straight ahead, committing to one frame before it begins the next. However, the research on rhyme planning suggests that it also works a little like pose-to-pose animation, holding a destination in mind before the in-betweens are drawn. The blue arcs in the full-attention columns behave like onion skinning, with each frame looking back through the earlier ones before it is resolved.

Similarities and differences

The comparison is useful because both systems compute with very large numbers of simple units whose connections were shaped by experience. It becomes misleading if it suggests that the units are the same kind of thing. The most important correction is that a parameter is closer to a synapse, a single connection between neurons, than to a neuron itself.

Is it just a tool?

A tool, in the ordinary sense, is specified. Each of its behaviours can be traced to a decision someone made. None of the 2.4 trillion numbers in this model was written by a person. They were set by an optimisation process run over a vast archive of human writing, and what they encode has to be discovered after the fact. The methods used to discover it look more like neuroscience than software engineering.

That research has found structure that nobody designed. When Anthropic’s interpretability team traced a model writing a rhyming couplet, they found it selecting the rhyme word before beginning the line, then composing the line to arrive there (Lindsey et al., 2025). This finding needs some care. Saying that the model plans describes what it does; it does not mean that the model intends anything. Even so, planning of this kind is not something we would expect from a tool.

The opposing view

There are strong arguments against this position. Bender and colleagues argue that a language model reproduces the statistical form of language without access to meaning, and that its fluency invites us to project minds where there are none (Bender et al., 2021). From that perspective, an image of nervous tissue could be seen as part of the problem, because it makes arithmetic look alive.

The piece is not intended to settle this debate. What it offers is a way of looking at the space between the two positions. The system has no body, and it does not keep learning once it has been trained, but nor is it an instrument whose behaviour someone authored. For practitioners, I think it is more useful to treat it as a collaborator whose cognition is partial and unfamiliar, and to work with it on those terms.

Method and sources

What is real here and what is simulated
  • Real: the structure. The figures used throughout are 92 layers, 512 routed experts with 10 active plus 1 shared, 23 full-attention and 69 linear-attention layers, 64 query heads, an 8,192-wide stream, a vocabulary of 248,320 tokens and the token-by-token generation loop. Each is triangulated across the vLLM launch post, the HF architecture viewer and APXML. The count of shared experts comes from APXML alone.
  • Simulated: which experts fire. No model of 2.4 trillion parameters can run in a browser, so routing is a deterministic stand-in in which the same word always takes the same path. It is also clustered by position to make specialisation visible. Real routers specialise more by syntax and token type than by tidy topic.
  • Simulated: the tokenisation is approximate, and the token IDs and probabilities are illustrative. I wrote the replies to the four sample prompts for this piece. Replies to your own prompts appear as masked tokens, because inventing text and attributing it to the model would be false.
  • Approximate: compute is estimated with the standard rule of thumb of about two floating-point operations per active parameter per token, roughly 190 GFLOP. The estimate ignores the cost of attention.
